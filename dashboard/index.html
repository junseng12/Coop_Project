실험 기록 — M1~M4 비교
#지점실제 kWh보고 kWh청구결과탐지 경계 / 비고
작동 순서(발표 권장). 실험 제어 패널에서 한 번에 한 지점만 고릅니다. ① 정상 → start → 완충 → 실제 전량 청구 확인(기준) · ② M1 선택 → reset → start → 완충 시 자동 종료, 흐름도가 M1에서 변조를 표시하고 청구가 낮아짐. 실험 기록에 한 줄 쌓임 · ③ 같은 식으로 M2 · M3 · M4를 하나씩 → 네 지점이 각각 독립 실행되고 아래 표에서 탐지 경계가 어떻게 다른지 비교 · ④ OCPP TLS 체크 후 M2를 다시 → 전송 암호화로 차단되어 정상 청구(현실 TLS 2/3 반영) · ⑤ ▶ 흐름 재생 으로 자동차→충전기→결제기 서사 반복. 상단 발표 결과 ↗ 는 종합 정리입니다.
동작. start → SLAC·ISO 15118-2 TLS·PnC 계약 인증·전력 인출 순으로 진행되며 계량이 누적됩니다. 완충(SoC 100%) 또는 stop 시 거래가 종료되어 OCPP TransactionEvent → OCPI CDR → 청구서가 생성됩니다. inject M1~M4 <%> 로 특정 계층에서 실제의 N%만 보고하면(많이 충전·적게 청구) 청구서가 작아지고 어느 계층 대조에서 탐지되는지 표시됩니다. 금액 산식은 billing/engine.py와 동일(통화별 소수자리·ROUND_HALF_UP)하며 SIMULATED_INVOICE_NOT_PAID 모의 명세입니다. 실제 결제·물리 계량·계량 서명은 포함하지 않습니다.
